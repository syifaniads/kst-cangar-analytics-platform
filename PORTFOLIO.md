## Website case-study version

### Problem

KST Cangar's operational information was recorded across fragmented/manual processes, making stock, booking, and financial monitoring difficult to centralize.

### Solution

Our six-person capstone team developed an integrated WordPress-based operational platform with dashboard monitoring, Stock Opname, facility booking, financial records, RBAC, and a public information page.

### My responsibility

I focused on the admin-facing frontend and frontend-backend integration. I implemented dashboard views, Stock Opname and Booklist ATP interfaces, connected those interfaces to the REST API, handled login/logout integration and role-aware UI, and debugged data-contract issues during system integration.

## Interview talking points

A useful way to explain the project in an interview:

1. **Start with the operational problem**, not the framework: fragmented records and difficult monitoring.
2. **Explain your boundary of ownership**: admin frontend, dashboard visualization, API integration, auth/RBAC presentation, debugging.
3. **Describe an integration challenge**: backend response structures changed, so frontend parsing and module integration had to be adjusted and retested.
4. **Discuss trade-offs**: the team moved to WordPress during the project, which accelerated integrated delivery but required careful separation between custom frontend behavior and WordPress conventions.
5. **Acknowledge limitations**: dashboard performance/mobile optimization and an RBAC UI issue remained follow-up items.
